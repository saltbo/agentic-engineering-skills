# 订单 API 设计说明

本次产物只覆盖创建、读取和按状态分页列出订单，共三个操作：`POST /orders`、`GET /orders/{orderId}`、`GET /orders`。采用 OpenAPI 3.1.0；当前没有既有客户端或工具链约束，后续接入生成器时需要验证其支持情况。URI 不带版本；`info.version` 表示文档版本，不额外引入 API 版本请求头。

订单是独立资源：由服务端分配全局唯一且不可变的 opaque ID，以 `/orders/{orderId}` 为唯一规范地址。归属 Orders 领域，所有操作只有一个 Orders tag。`tenantId` 是不可变归属，`status` 和 `totalCents` 是订单内的标量状态，没有独立身份或生命周期，不拆分为资源。响应直接返回订单，并提供绝对 `links.self`；未定义租户 API，因此不虚构租户端点。

创建请求仅包含非负整数 `totalCents`，不接受 ID、租户或状态。金额上限为 JavaScript 精确整数上限，避免操作员 UI 丢失精度。**设计假设**：租户已有一种固定结算币种，金额以该币种的分计；若产品要求多币种或币种切换，需要扩充契约。创建状态为 `pending`，权威履约系统可将其推进为终态 `shipped`。发货执行、订单编辑、删除及保留期规则不属于已要求的操作，不据此添加写接口。

项目统一选页码分页：小型操作员 UI 明确要求精确总数和直接跳页，足以支持此选择，无需先追问规模。参数为一基 `page`、默认 50 且最大 100 的 `pageSize`，可选枚举 `status`；响应为 `items` 和包含 `page/pageSize/totalItems/totalPages` 的 `pagination`。授权和过滤先于精确计数，数据与总数来自同一次请求的读快照。固定按唯一 ID 的 ASCII 字节序升序排列。请求之间不承诺快照，插入或状态变化可能移动页边界。空集合总页数为 0；越界页面返回 200 和空 items。导航只在 `Link` 响应头中，保留过滤及分页条件。

认证方案为标准 bearer，具体发行方由部署选择。认证产生可信主体和唯一租户上下文，授权独立验证操作权限与订单归属。客户端不得通过普通 body/query 指定租户权威。无效凭证返回 401 和 `WWW-Authenticate`；操作权限不足返回 403；跨租户订单与不存在订单统一 404，列表及计数不泄露其他租户数据。

订单重复创建可能产生业务成本，因此 POST 要求 `Idempotency-Key`，采用本项目明确的引号字符串格式；这是项目约定，不把草案当成已发布 RFC。契约定义 24 小时保存期、主体/租户/方法/路径作用域、规范化 body 指纹、原成功响应重放、不同内容的 422 和处理中重复请求的 409。原结果和订单需原子保存；超期重试可能重复，不能宣称恰好一次。GET 可安全重试。成功创建返回 201、Location 及订单本体；订单响应含强 ETag。所有响应带新生成的 Request-Id 和 no-store，失败统一 Problem Details。

本地检查已通过：JSON 解析、全部本地引用、312 项结构断言、全部嵌入示例、非法输入、分页边界和 BEP 两条资源路径检查。使用 Python 3.13.7，无网络或凭证访问。环境未安装 `jsonschema` / `openapi_spec_validator`，因此本次验证是明确限定范围的离线结构及示例检查，不能替代完整 OpenAPI 元模式验证。没有服务端实现，也未宣称通过运行时契约测试。

复现：依次运行 `python3 build_contract.py` 和 `python3 validate_contract.py`。正式接入工具链时运行完整 OpenAPI 验证，并用真实实现验证租户隔离、同快照精确计数与创建去重的原子性。
